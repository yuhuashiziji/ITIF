本轮确认的功能与隐私边界问题已修复，修复版通过39项Python测试、前端行为回归和干净ZIP解压验证。发布包的文件与内容扫描未发现本机用户路径、私人邮箱、手机号格式或常见密钥格式；不包含个人配置、缓存、日志、抓取页面和备份。

## 已确认并修复

### P1 · 翻译中的私有内容边界不完整

**要求**：README及docs/PRIVACY.md承诺输入、配置和收藏不发送外部翻译。**触发**：自定义订阅的名称/标题出现在抽屉、首页或精选，个人关注词出现在精选理由，收藏内容在轮询后进入侧栏副本。旧翻译遍历只跳过表单及主收藏卡，不能自动识别这些派生内容。**后果**：这些文本存在进入外部翻译请求队列的路径；未向第三方发送用户真实隐私来做验证。

**证据链**：server/editorial.py:50,68（自定义来源、精选的生产者）→server/app.py:122及server/domestic.py:26（前端投影）→每日聚合站_融合版.html:527与server/editorial.js:10（文字呈现）→server/translate.js:20,23（收集与发送）。server/reader.js的renderTop10还能生成收藏副本。

**排除的反证**：仅跳过input或配置表单不能保护其派生展示；仅跳过主收藏卡不能覆盖侧栏。**修复**：自定义来源默认private；私有标记经首屏、轮询、精选、事件和旧存档传递到translate=no；翻译另行跳过关键词说明、订阅名称、收藏副本与订阅预览。**验证**：后端私有标记贯通测试、旧存档保护测试，以及执行真实翻译收集器的公开/私有文本节点夹具。私有夹具均未进入结果队列。

### P2 · 收藏和未读“展开全部”使用了错误数据源

**要求**：展开应继续使用当前筛选结果。**触发**：收藏6条后展开，或在未读列表展开。**问题**：原入口按NODES找来源，而收藏是reader.js合成的saved-reader，不存在于NODES；未读筛选也只存在于visibleNodes返回值。收藏会抛TypeError，未读展开会绕过过滤。

**证据链**：server/reader.js的visibleNodes包装与收藏合成 → 每日聚合站_融合版.html:604的展开处理。**反证检查**：reader重绘没有向NODES写入收藏，也没有重写展开处理。**修复**：从visibleNodes取当前实体，并处理已移除来源。**验证**：修复前最小执行得到TypeError；修复后浏览器实际加入6条、展开显示6行；测试收藏已恢复。Node行为测试另覆盖未读及来源移除。

### P2 · 非对象JSON会导致接口异常断开

**触发**：对/api/settings、/api/source提交[]等合法JSON。旧处理直接调用obj.get，AttributeError不在捕获范围。**修复与证据**：server/app.py:179,212明确检查字典，/api/feeds同样限制；翻译接口自身已有类型校验。**反证**：前端通常发送对象不能约束其他本地调用方。**验证**：四个POST入口均用数组测试，返回400，未修改配置。

### P2 · A股缓存保存与数值边界

**触发**：只有A股更新成功时重启，更新没有立即保存；或上游返回NaN时污染JSON数值。**证据链**：server/app.py:52–63的A股生产者与save；server/live.js的JSON消费者；server/market_adapters.py:number已有有限数值契约。**反证**：其他RSS/行情随后保存只能偶然掩盖未持久化。**修复**：A股分支明确save并统一数值校验，缺失/零涨跌不再标为红色上涨。**验证**：保存调用和非有限数值拒绝测试。

### P2 · 历史快照导出不能只信旧缓存标记

**触发**：旧缓存缺少snapshot字段，而来源目录已经将其标为历史快照。**证据链**：server/app.py:151的导出筛选 → server/rss_engine.py:export。**反证**：当前缓存碰巧有标记不保证升级或迁移后的缓存也有。**修复**：以当前启用目录且非快照的来源集合为准，再筛选缓存。**验证**：构造缺标记的旧缓存，历史条目不出现在导出RSS。

## 网络与解析补强

- **DNS重解析窗口**：原public_url验证DNS，随后urllib再次解析才连接，两个结果可能不同。app.py的request及rss_engine.py:fetch已统一使用public_http.py:checked_connection，在发送HTTP之前校验实际对端IP。公开抓取直连，不借代理隐藏对端地址。内网对端拒绝测试、HTTP/HTTPS绑定测试通过；实际公开HTTPS RSS请求成功。未实施真实DNS重绑定攻击，不能称为已验证的线上利用。
- **XML多编码声明**：rss_engine.py:14原字节扫描不能识别UTF-16中的DOCTYPE/ENTITY；现在识别空字节编码形式并拒绝。测试覆盖UTF-16。没有将其描述成已证实的本地文件读取漏洞。
- 来源名称、描述和节点标识按HTML上下文转义；回归夹具含尖括号。此处主要避免误解析，没有把用户自输文本造成的自我影响夸大为远程攻击。
- 禁止被第三方页面框架嵌入，外链不发送Referer；Host、Origin、固定静态资源路由保留。访问配置、缓存、环境文件及目录穿越式路径均返回404，外来Host/Origin返回403。
- 翻译记录及时清除已断开的DOM节点，避免定时重绘后一直保留旧文字节点。
